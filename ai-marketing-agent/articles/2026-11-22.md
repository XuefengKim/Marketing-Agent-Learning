## 1. Claude Agent SDK Meta Ads Guardrails & Human Approval (2026) — PandaWM，2026-11-16

https://www.pandawm.com/blog/claude-agent-sdk-meta-ads-guardrails-human-approval-en.html

一篇可以直接照抄的护栏搭建指南，讲如何用 Claude Agent SDK 通过 Meta 官方 ads MCP 服务器起草 Facebook 广告，同时让花钱的动作始终留在人手里。核心是六层护栏：Meta 侧只支持 Employee-role 系统用户 token（Admin-role 不支持），且写操作默认建 PAUSED 状态、激活是需单独确认的独立工具；工具白名单只放必需的 MCP 工具；`can_use_tool` 回调做审批——读操作自动放行、激活一律拒绝、其余写操作逐条问人（附完整 Python 代码）；PreToolUse hook 做第二道锁，扫描工具输入里所有含 budget 的字段、超过 200 上限直接拒（附 hook 脚本）；最后用 Meta 的 activity log 加自有日志做审计。文末给出分阶段上线节奏：第一周只读、第二周只建暂停草稿、第三周起才做小额改动且 hook 已就位；“无人值守激活、无上限预算改动”永远不做。官方文档均于 11 月 16 日当日核对过。

**为什么读（0→1 搭建者）：** 护栏层最落地的施工图——从 token 权限、审批回调、预算上限 hook 到审计日志和上线节奏，六层机制都有代码和配置可以直接搬进自己的 agent；“激活工具永远不让 agent 碰”这条规则尤其值得定为硬性红线。属于护栏 + 执行层，约 L0–L1。

## 2. Contextual signals, bought by an agent — AgenticAdvertising.org（Florian Mühlhans，True Relevance），2026-11-16

https://adcontextprotocol.org/perspectives/contextual-signals-bought-by-an-agent-mwjb0moo

AdCP 官方组织上的一篇生产实测手记：买方 agent 如何用自然语言买到一段上下文定向人群，全程只需四次工具调用。买方 agent 发一句自然语言 brief（“为计划阿尔卑斯徒步假期的人找信号”），约 10 秒拿到窄、中、宽三版草稿；一句话 refine（“只保留多洛米蒂山区小屋徒步，排除滑雪与冬季运动”）后得到新草稿；确认后才真正创建 segment 并注册到买方选定的平台（示例是 Index Exchange，6 秒返回 segment ID），PubMatic 与 The Trade Desk 同样支持；最后买方回传曝光数据供计费。关键设计是 LLM 只负责把 brief 翻译成结构化 segment，不做排序、不直接买量；agent 已公开列入 AdCP 注册表并通过合规检查，用 OAuth 登录，任何 AdCP/MCP 客户端（包括 ChatGPT、Claude Code）都能接。作者也坦白了未完成的部分：按投放效果自动放宽/收紧 segment 的回路还在计划中，下一步是绕过 DSP、让买方 agent 直接对接卖方 agent（尚未建成）。

**为什么读：** 这是 AdCP 从协议文档走向真实交易的第一个完整走通案例——四次调用的时序、6 秒激活、segment ID 回传、按账户计费，说明“agent 之间谈定向、谈交易”已经不是概念图；同时它划清了模型能力的边界（只做翻译不做决策），这对设计自己系统的职责分工有直接参考价值。属于执行层 + 协议层（AdCP），约 L1–L2。
