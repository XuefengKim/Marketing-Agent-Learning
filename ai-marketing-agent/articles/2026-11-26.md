## 1. What an AI Marketing Agent Actually Does, and How to Build a Guarded One — SitePoint（Sophie Marks），2026-11-24

https://www.sitepoint.com/what-an-ai-marketing-agent-actually-does-and-how-to-build-a-guarded-one/

先帮读者拆穿一个概念泡沫：很多标榜 agent 的营销产品只是“定时任务换了个名字”或 if/else 分支加一段模型文案。真正的 agent 是目标 + 工具集 + 感知—推理—行动—观察的循环，判断标准是“如果能提前画出完整决策树，那就是自动化；如果路径取决于模型看数据后的决定，才是 agent”。文章随后给出一个可直接照抄的最小受护栏约束的预算 agent：Python 实现，Guardrails 用数据类写死（白名单 campaign、日预算上限、单次变动超 20% 转人工、每轮最多 5 个动作），check() 函数对每次工具调用返回 run / approve / deny 三种裁决，全部在代码里执行、绝不依赖提示词；附 pytest 测试覆盖小改动放行、大改动待批、超上限拒绝、未知工具拒绝、无限循环被动作上限截停。还给了 build vs buy 的判断框架（自研编排 + 采购高频窄任务）、可移交/不可移交的任务清单（可移交：写文案变体、汇总表现、暂停明显跑崩的广告；须监督：跨账户调预算、改价改折扣、对外发声），以及三类失效模式：失控花钱、脏上游数据、缺审计日志（引用 Deloitte：近四分之三企业计划两年内部署 agentic AI，只有 21% 称已有成熟治理模型）。

**为什么读（0→1 搭建者）：** 护栏层最落地的工程课——护栏不是写在文档里的政策，而是写在代码里的 check() 函数；最小实现加测试不到两百行，可直接作为自己预算 agent 的骨架起点。属于护栏 + 执行层 + 决策层，约 L0–L2。注：文中举例提及一家厂商（Larven）的 Meta 广告 agent，作者已明确标注按厂商自述对待、正文不依赖它。

## 2. Agentic Budget Reallocation: Closing the Approval Gap — Influencers-Time（Jillian Rhodes），2026-11-14

https://www.influencers-time.com/agentic-budget-reallocation-closing-the-approval-gap/

核心论点是预算动作与其他 AI 动作本质不同：建议错了只是一场会，执行错了是真金白银——“能描述预算变化的 agent 是研究工具，能执行预算变化的 agent 是拿着信用卡的员工，按员工来治理它。”文章先列五种最常见的失效模式：指标博弈（agent 只优化看得见的末次点击 ROAS，饿死上层漏斗）、失控再分配（短期峰值诱使 agent 重仓，峰值一过钱已花完）、品牌安全漂移、合同冲突（挪走了已承诺给创作者/媒体的预算）、静默错误（追踪像素坏了，某渠道看起来像奇迹）。随后给出四道护栏：硬上限（单次变动 cap、日/周累计 cap、渠道上下限、总预算锁定、冷却窗口）；三级审批（小额自主、中额通知后执行、大额/新渠道/合同支出先批，且负责人必须是一个具名的人而非“团队”）；CFO 也挑不出毛病的日志（动了什么钱、依据哪份何时的数据、预期结果、落在哪个审批档、通知了谁、有无被撤回，每周对照预期与实际复盘）；熔断与回滚（暂停再分配、恢复到上一个人工批准的分配，两者上线前都要实测，外加 CPA 超阈值、花费偏离计划、数据断流时自动停机升级）。最后给出上线顺序：影子模式（只建议不执行，对照团队决策）→ 窄试点（一个预算切片、一对渠道、紧 cap）→ 凭证据放宽 → 季度复评。

**为什么读：** 护栏层 + 决策层（预算分配）的运营手册——SitePoint 那篇讲护栏怎么写代码，这篇讲护栏怎么定规则、怎么上线、出了事怎么停；两者拼起来才是一套完整的预算 agent 治理。属于护栏 + 决策层，约 L1–L3。注：页面文末附带该站的代理商榜单，与正文无关。
