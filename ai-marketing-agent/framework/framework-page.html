AI 营销 Agent：先建框架，再读文章

这个领域其实有两套不同的自动化，混在一起谈是大多数 0→1 计划走偏的起点。先把它们分开，再看平台、架构与度量，最后按顺序读完 12 篇精读。

平台自动化 ≠ Agent 自动化

Meta Advantage+、Google Performance Max / AI Max、TikTok Smart+ 已经在各自的围墙花园里做竞价、扩量和创意组装。你的系统不取代它，而是在它之上感知、决策、通过 API 执行——并给它装上护栏。

创意就是定向

自 Meta Andromeda（2024 年 12 月）起，检索引擎直接读广告本身来决定它能触达谁。0→1 的第一笔投入应该是创意多样性 + 干净的转化信号，而不是更精细的人工定向。

< 5%真正的全自动还很稀有

据 Gartner（经 Adweek 2026 年 10 月报道），2025 年高度自动化的营销用例不足 5%，预计 2028 年到 15%。正确路径是分级爬梯：审批门逐步收窄，而不是一步到位。

01全景地图：营销 Agent 到底覆盖什么

六个职能。每一格都分三层看：Agent 做什么、平台已经替你做了什么、以及你仍然必须自己建的部分——第三列才是你的工作量所在。

创意生成

Agent 做
从 brief 出发产出角度 / 钩子、文案、图视频变体、本地化与尺寸适配；生成必须以产品数据库为依据，而非模型自由发挥。
平台已做
Meta Advantage+ Creative、Google AI Max 文案定制、TikTok Symphony（Smart+ 内）都能生成、扩展、混剪素材。
你仍要建
品牌事实源（规范 + 主张数据库）、生成提示词、多层审核、疲劳检测、变体→原型（archetype）的追踪。

媒体购买 / 竞价

Agent 做
设定与调整预算、出价、上限；暂停 / 关停 / 放量广告组；决定广告系列结构。
平台已做
Smart Bidding（Google）、Advantage+ 预算与版位优化、Smart+ CBO——都在黑盒内部完成。
你仍要建
决策策略：何时干预、用什么阈值，以及 LLM 无权突破的硬上限。

预算分配

Agent 做
按边际增量回报在跨渠道 / 跨系列之间再分配预算。
平台已做
只有系列内部的分配（如 PMax 在 Google 各渠道间分配）。
你仍要建
以增量校正后的回报（而非后台 ROAS）为输入的跨渠道分配器，加上节奏控制与日 / 周上限。

受众 / 分群

Agent 做
用一方数据、相似人群、意图信号构建与刷新分群；排除已有客户。
平台已做
Advantage+ Audience 把你的输入当作建议并自动扩展；AI Max 无关键词匹配；Smart+ 自动定向。
你仍要建
以数据形式定义的受众、排除 / 抑制逻辑、合规的身份方案（不依赖用户级追踪）。

度量 / 增量

Agent 做
地理留出（geo holdout）、增量提升研究、MMM；把结果转成每渠道的校正系数。
平台已做
平台自家的 lift 研究（Meta / Google Conversion Lift，用户级最低约 $5,000）——等于平台给自己判卷。
你仍要建
独立度量：以自有销售 / CRM 为事实源，GeoLift、Meridian GeoX，以及用实验校准的 MMM。

报告 / 洞察

Agent 做
自然语言的业绩叙述、异常检测、根因分析、下一步行动建议。
平台已做
Ads Manager / Google Ads 报表；PMax 的渠道级报表（2025 年补齐）。
你仍要建
统一的跨渠道事实表（花费、归因收入 vs 增量收入、毛利），以及每一次 Agent 动作的审计日志。
两个容易浪费工夫的误区。其一，「Agentic」≠「自动化」：一条「CPA > $X 就暂停」的规则是自动化；Agent 是在非结构化状态（创意、市场、漏斗）上推理、并通过工具在多个动作中做选择。其二，市场上有两种 Agent：替广告主在围墙花园里买量的（你要建的这种），和买卖双方之间的 Agent 对 Agent 交易（AdCP / AAMP，目前以 CTV 和媒体方为主，还很早期）。

02三大平台今天自动化到什么程度

先搞清楚每家平台「替你决定了什么、还留给你什么」，才知道你的系统该写哪一层。平台给出的效果数字均为其官方口径，当方向看，不要当承诺。

Meta
Advantage+ · Andromeda · GEM

它决定

谁有资格看到广告（检索短名单）、排序与竞价、预算、版位、创意变体。

你保留

目标、预算 / 上限、创意素材、品牌控制、受众建议、排除项。

关键事实

  • Andromeda（2024-12-02，Engineering at Meta）：检索把「数千万候选」收窄到「几千」，召回 +6%、广告质量 +8%（选定人群），模型容量 10,000×，跑在 NVIDIA Grace Hopper 与 MTIA 上。
  • GEM（2025-11-10 索引）：LLM 级教师模型蒸馏进排序器；Meta 称 2025 Q2 Instagram 转化 +5%、Facebook Feed +3%。
  • Meta（2025 年 4 月）：「创意多样化是找到最相关受众的最佳杠杆」——创意即定向。Advantage+ 已是新建销售 / 线索 / 应用系列的默认。
Google
Performance Max · AI Max · Smart Bidding

它决定

渠道、受众、素材组合、出价、落地页（最终到达网址扩展）、关键词之外的查询匹配。

你保留

预算、目标（tCPA / tROAS）、素材组与受众信号、品牌包含 / 排除、否定词、网址控制、意向地域。

关键事实

  • PMax：一个系列跑遍 Search、YouTube、Display、Discover、Gmail、Maps，素材按素材组组织，Google AI 实时组装广告。
  • AI Max（2025-05-06）：搜索词匹配（广泛 + 无关键词）、文案定制、最终到达网址扩展；Google 称通常 +14% 转化、CPA / ROAS 相近，精确 / 词组为主的系列可达 +27%。
  • 2025 年 PMax 补齐了渠道级报表与完整搜索词报表（4–8 月）。
TikTok
Smart+ · Symphony

它决定

定向、预算 / 出价（CBO）、版位、创意组合。

你保留

目标 / KPI、预算、地域与语言、素材；自 2025 年 10 月起自动化可按模块开关（定向 / 预算 / 创意 / 版位分别切换）。

关键事实

  • Smart+（Smart Performance Campaign 的后继，2024 年 4 月起）：单系列最多 30 个广告组、每组 30 个素材组、每素材组 50 条创意。
  • Smart+ Catalog Ads 在封闭测试中 CPA −36%（TikTok 内部数据，2025）。
  • Symphony Automation：推荐创意 + 自动增强，含 50+ 语言配音。

新兴形态：Meta 的 Muse for Small Business（2026-09-29，索引）、Google 的 Ads Advisor / Analytics Advisor（2025-11-12，索引）、Amazon Ads Agent（2025 年 11 月，索引）都是平台内的对话式助手——能分析账户、起草系列、建议修改，但 Meta 的规则是「未经你批准，不发布、不发送、不花钱」。它们是审批交互的参考，不是可依赖的基础设施。

执行层：你真正要编程对接的 API

三家都免费（有广告账户即可），鉴权均为 OAuth 2.0（Google 另需开发者令牌）。版本号迭代很快，动手前务必回官方文档复核。

Meta Marketing API

系列 / 广告组 / 广告的增删改查、自定义受众、Ads Insights、Conversions API（服务端事件），对象层级与 Ads Manager 一致。Graph API，约每 4 个月一个版本（v26.0 于 2026-07-29 发布，据二手指南）；权限 ads_read / ads_management；服务端用系统用户令牌。Meta 已于 2026 年 7 月向所有开发者开放 Ads MCP server（索引）。

Google Ads API

系列、素材组、预算、出价、GAQL 报表；PMax 通过原子化批量 Mutate 创建（预算 + 系列 + 素材组 + 素材）；AI Max 设置自 API v21 起可用。不开放的：Smart Bidding 内部逻辑、竞价数据、竞品出价。

TikTok Marketing API

系列 / 广告组 / 广告管理、Spark Ads、视频上传、受众同步。需要应用审核与企业验证，有速率限制。

信号管道（不可谈判）：服务端转化事件（Meta Conversions API、Google 增强型转化 / 离线转化导入、TikTok Events API）同时喂给平台和你自己的数仓。平台的优化质量上限，就是你回传的转化信号质量；而你的度量必须用自有销售 / CRM 数据，绝不能只信平台转化数。

协议层（了解即可）：MCP（Anthropic，2024 年 11 月，现属 Linux Foundation）管 Agent↔工具；A2A（Google，2025 年 4 月）管 Agent↔Agent；AdCP（2025 年 10 月，AgenticAdvertising.org）管 Agent 买量任务；IAB Tech Lab 的 AAMP / ARTF 管程序化实时竞价。0→1 先用原生 API + MCP，AdCP / AAMP 是要盯的互操作赌注，不是起点（见精读 #9）。

03一套自动投放系统的架构

四层加一圈护栏。最重要的一条分工原则：花钱的决定权在代码里，不在 LLM 里——上限、计数、发布由确定性代码把关，LLM 只在边界内做语义工作（排序、起草、解读）。

DATA LAYER · 数据层

事实与信号

一方数据：CRM / 订单、产品目录 + 主张数据库、品牌资产。平台数据：Insights / GAQL / TikTok 报表（花费与投放）。信号回传：CAPI / 增强型转化 / Events API。数仓：统一的花费 × 收入 × 毛利，粒度到地域 × 天。

▼
DECISION LAYER · 决策层

Agent + 确定性策略

感知：流式 / 批量指标、创意疲劳、异常、节奏。推理：LLM Agent（分析师 → 策略师）+ ML 模型（饱和曲线、MMM 边际 ROI、创意评分）。策略层是代码而非 LLM：预算上限、关停 / 放量规则、品牌与合规检查、审批路由。

▼
EXECUTION LAYER · 执行层

工具化的 API 调用

对 Meta / Google / TikTok API（及 MCP server）的工具封装；变更必须幂等、可 dry-run 预演；每一次调用都留日志。

▼
FEEDBACK / EVAL LOOP · 反馈与评估环

两个回路

短回路：平台指标 → 再分配 / 刷新创意。长回路：地理留出 + MMM → 校正系数 → 反哺分配器先验、创意策略与预算切分。评估：离线（历史回放、黄金集）+ 在线（影子模式、留出）；每一个决策都要有可追溯的 trace（如 LangSmith）。

护栏环绕所有层：硬上限、允许清单、主张核验、人工审批门。预算护栏全部写在 LLM 之外的代码里：账户 / 日硬上限、单次变更上限（如预算 ±15% / 天）、最低 ROAS / 最高 CPA 触发自动暂停、关停规则（如 3× 目标 CPA 且零转化）、节奏告警、全局急停开关。每次变更记录操作者、理由与变更前后状态——2025 年 11 月曾有 Meta 系列在首小时花掉日预算 150%+ 的报道，这正是第一个要防的失败模式。

04自主阶梯：一次只上一级

每一级都有明确的「毕业标准」。没有通过评估，就不要放宽权限——这是整份框架里最可执行的一页。

L0

手动 · 只读

Agent 什么都不做，只有看板和告警；全部决策与执行由人完成。

毕业标准：数据层可靠；一个渠道以只读方式经 API 跑通。

L1

辅助 · 只建议

Agent 起草动作并附理由，不做任何写入；人在应用内逐条批准 / 驳回。

毕业标准：建议被接受或被正确驳回的比例 > 90%；评估全绿。

L2

半自动 · 有界写入

Agent 在上限内执行预批准的动作类（如 CPA > 3× 目标自动暂停、每日预算转移 ≤ 15%）；人每天复查队列，批准新创意与预算上调。

毕业标准：连续 4–8 周无护栏突破；影子模式结果与人工一致。

L3

自动 · 受监督

完整回路，包括创意生成与上线，全部在预算包络与品牌锁定之内；人设定目标与上限、每周复盘、处理异常。

毕业标准：回报经增量验证；事故预案实测过。

L4

全自动 · 愿景

在包络内无限期运行，只上报异常；人只做治理：目标、上限、品牌事实源、审计。

现状：今天高度自动化的营销用例不足 5%（Gartner，经 Adweek 2026 年 10 月报道）。

0→1 推荐搭建顺序

只读数据 + 报告 Agent——先在 Meta 上把数拉通、把报表做对。
确定性规则——暂停 / 关停 / 节奏，全部经人工批准执行。
创意生成流水线——配齐五层审核（见概念区与精读 #12）。
预算分配器——以增量校正后的回报为输入，而不是后台 ROAS。
扩渠道——再接 Google、TikTok，收拢到一个渠道抽象层后面。
逐级放权——按阶梯一次放宽一个动作类。不要一上来就做能花钱的自由多 Agent 群。

05搭建者必须吃透的概念

九个概念，按「会在哪一步咬你」排序。前三个决定架构，中间三个决定安全，最后三个决定你算出来的数字能不能信。

工作流 vs Agent

Anthropic（2024 年 12 月）的定义是这个领域的标准词汇：工作流 = LLM 与工具走预先写好的代码路径；Agent = LLM 动态决定自己的流程与工具使用。五种可组合的工作流模式——提示链、路由、并行化、编排者-执行者、评估者-优化者——覆盖了大多数真实需求。原则：用能通过评估的最简模式；只有当路径无法预先写死、但进展可以验证时，才上真正的 Agent。先直接调 LLM API，框架（LangGraph、CrewAI 等）的抽象会遮住提示词、让调试变难。

工具使用 / Agent-计算机接口

设计工具要像设计 UI 一样认真：命名精确、schema 严谨、文档清楚、输出结构化、带幂等键。再强调一次分工：LLM 永远不决定「要不要花钱」——上限、计数、发布由代码决定，LLM 只在边界内做语义判断。

评估即产品

离线评估（黄金创意集、历史回放）、在线评估（影子模式：Agent 提议、人执行、再对比）、决策 trace，三者缺一不可。测不了 Agent 的决策质量，就不能安全地放宽它的权限。Anthropic 的三条原则：简单、透明（展示规划步骤）、工具设计用心。

幻觉 / 主张风险

模型会一本正经地编造价格、规格、折扣和统计数字。对策是检索 grounding（只从产品 / 主张数据库生成）+ 主张核验层（凡无法对事实源核验的一律拒绝）+ 抽样批次审计。落地细节见精读 #12 的五层流水线。

品牌安全：两层

适配性（广告出现在哪里，平台有品牌安全模块）与身份一致性（创意是否还是这个品牌：语调、色值、字体、主张）。规模化之后真正的杀手不是灾难性错误，而是大量「略微跑偏」的变体在一个季度内稀释品牌。新兴解法是 brand.json——品牌自有域名上的机器可读品牌事实文件（AdCP 3.0），见精读 #11。

预算护栏

确定性、在代码里、在 LLM 之外：账户 / 日硬上限、单次变更上限、ROAS 下限 / CPA 上限触发自动暂停、关停规则、节奏告警、全局急停。每次变更记录操作者、理由、前后状态。超支失控（见 03 节的 150% 案例）是第一个要设计防御的失败模式。

归因 vs 增量 vs MMM：三角互证，不要只选一个

  • 归因（末次点击 / MTA）：哪个触点「认领」了转化。适合日常运营；系统性高估再营销与品牌词搜索；受隐私变化侵蚀（仅浏览器追踪会漏掉 30–40% 的转化）。
  • 增量（地理留出、人群留出、平台 lift）：这笔花费导致了什么，相对于反事实。预算决策的金标准；慢（数周）、粗（渠道级）。
  • MMM（Meridian、Robyn）：用饱和与衰减（adstock）回归销售与花费的关系；常开、跨渠道、隐私耐久（聚合数据）。但本质是相关性，必须用实验结果作先验来校准。

运行规则：日常用归因，每季度对主要渠道做地理实验（产出 = 对平台 ROAS 的一个校正系数），跨渠道分配用 MMM——并且要复测，因为平台一变，系数就会漂移。

创意即定向，疲劳是时钟

Andromeda 之下，多样化创意（不同角度、钩子、形式、人群）是触达的主要杠杆；近似重复的创意会被算作同一条。创意死得很快——一项 2026 年对 290 万条 Meta 广告的分析显示中位寿命仅 3 天——所以系统需要持续刷新节奏，而不是一次性产出一批。

学习期 / 信号质量

平台每个广告组每周约需 50 个转化事件才能退出学习期，改动会重置学习。你的 Agent 必须批量提交变更、尊重学习窗口、不来回折腾设置。干净、去重的服务端转化信号，比任何出价技巧都重要。

06数据锚点：平台 ROAS 有多不可信

Stella 基于 225 个地理实验（DTC 品牌，2024 年 8 月–2025 年 12 月）发布的增量 ROAS（iROAS）基准。这是目前少有的公开跨渠道对照：先记住量级，再谈优化。

各渠道增量 ROAS 中位水平（iROAS，×）

中位数上的金色须线为四分位距（IQR 1.36×–3.24×）。低于 1× 意味着每花 1 元、增量收入不到 1 元（未计毛利）。来源：Stella 增量测试指南（2026 年 6 月更新），样本为自选的 DTC 品牌，结果不可直接外推。另注意方向并非单边：Stella 的 46 个反向留出实验中，Meta 的实际增量平均比其报告值还高 21%——平台数字是两个方向都可能错。配合阅读：Haus 对 640 个 Meta 测试的分析也发现 Advantage+ 在测试中期看似好 9%、到结束时反而差 12%（见精读 #7）。

07工具与生态速览

AgenticAdvertising.org / AdCP（brand.json、AdCP 3.0）、IAB Tech Lab AAMP / ARTF、Prebid.org（参考销售 Agent）。Agent 对 Agent 买量正在这里标准化：盯着看，但围墙花园买量先别押在上面。
